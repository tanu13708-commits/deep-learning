# 10 — Practical Deep Learning & Debugging

## 71. How would you structure a deep learning training pipeline?

```text
Data Collection → Cleaning → Train/Validation/Test Split
→ Preprocessing/Augmentation → DataLoader → Model
→ Loss + Optimizer → Training Loop → Validation
→ Hyperparameter Tuning → Final Test → Save Model → Deployment
```

Important: avoid leakage, keep preprocessing consistent, track experiments, and save useful checkpoints.

## 72. How do you determine whether a model is actually learning?
Monitor training/validation loss and metrics. Check that loss changes meaningfully, predictions are not constant, validation performance improves, and the model beats a reasonable baseline. Training curves are very useful.

## 73. What would you check if training loss does not decrease?
Check data/labels, model-output/loss compatibility, learning rate, gradients, parameter updates, optimizer, input scaling, train/eval mode, and loss implementation. A powerful debugging test is whether the model can overfit a tiny batch.

## 74. What would you investigate if training accuracy is high but validation accuracy is low?
This commonly indicates overfitting. Check dataset size, train/validation distribution differences, leakage, class imbalance, augmentation, model complexity, regularization, duplicates, and label quality. Remedies include augmentation, dropout, weight decay, early stopping, more representative data, or reducing capacity.

## 75. How would you handle GPU memory limitations?
Reduce batch size or input resolution, use mixed precision, gradient accumulation, a smaller model, gradient checkpointing, and careful tensor/memory management. Avoid unnecessarily retaining computation graphs.

## 76. How would you make deep learning training reproducible?
Record random seeds, dataset versions, splits, preprocessing, architecture, hyperparameters, library versions, and hardware/software environment. Exact reproducibility can still be affected by nondeterministic GPU operations.

## 77. How would you save, load, and deploy a trained model?
Save model parameters/checkpoints using the framework's recommended format. Recreate the architecture if needed and load the parameters. For deployment, expose an inference function through an API or application such as FastAPI, Flask, or Streamlit. Production systems should also consider input validation, model versioning, logging, monitoring, latency, resources, and security.
